# EchoHire 离线面试评测 v1

## 目的与边界

这组评测检查 **OpenAI 不可用时的确定性备用追问和备用报告**。40 条题目与回答都是项目作者编写的虚构案例，独立于 `tests/interview.test.mjs` 的少量单元测试示例。标签表示下一步最有用的提问方向，不是候选人能力评分、真实面试官标注或模型 Agent 的效果。

评测不读 API Key，不发网络请求。运行器会把 `fetch` 替换为抛错函数；若代码意外尝试调用外部 API，评测会失败。`evals/interview-cases.mjs` 是冻结的挑战集；后续改进规则时，先用另建的开发样本设计规则，再用这组案例复测。不要为了提高本页数字直接修改挑战集标签。

## 数据与判定

五种预设追问方向各 8 条，共 40 条：

| 标签 | 含义 |
| --- | --- |
| `action` | 回答没有交代本人实际做了什么 |
| `result` | 有行动，但缺少行动后的结果 |
| `evidence` | 声称有结果，但缺少可核实的证据 |
| `tradeoff` | 技术方案有行动、结果和证据，却未解释方案取舍 |
| `none` | 信息足够，不应重复追问 |

每条案例只设定**最优先**追问方向；真实面试中可能有多个可问点。输出根据备用追问的实际问题文本归入上述类别。`other` 表示生成了无法归入这五类的问题。

指标：

- **追问类型一致率**：实际方向与预设方向完全相同的案例数 ÷ 40。`none` 作为独立类别。
- **追问决策一致率**：只比较“追问 / 不追问”，不检查方向。两项指标需要一起看。
- **各类精确率与召回率**：按该标签的预测数与预设数分别计算；分母为零时显示 `n/a`。
- **报告重点关键词命中**：仅对 32 条预设缺口案例检查备用报告的建议部分是否提及对应要素，先移除对原回答的引述。这只是浅层文本代理指标，**不能证明反馈正确或有帮助**。
- **引述一致数**：检查追问或逐题反馈引述的文字是否来自原回答。这只能检测引述中的文本是否存在，**不能验证语义真实性**。

## 默认规则基线

运行命令：

```powershell
node --experimental-strip-types evals/run-offline.mjs
node --experimental-strip-types evals/run-offline.mjs --json
node --experimental-strip-types evals/run-offline.mjs --summary-json
```

`pnpm eval:offline` 运行同一评测。机器可读的冻结结果见 [`evals/baseline.json`](../evals/baseline.json)。当前默认规则得到：

| 指标 | 结果 |
| --- | ---: |
| 追问类型与预设一致 | 35 / 40（87.5%） |
| 追问 / 不追问决策一致 | 38 / 40（95%） |
| 对完整回答的误追问 | 0 / 8 |
| 应追问却没有追问 | 2 / 32 |
| 报告重点关键词命中 | 26 / 32（81.25%） |
| 报告引述文字来自回答 | 40 / 40 |
| 实际生成的追问引述文字来自回答 | 30 / 30 |

按类召回率：`action` 8/8，`result` 5/8，`evidence` 6/8，`tradeoff` 8/8，`none` 8/8。完整混淆矩阵、精确率和案例编号在 `baseline.json` 中。报告与追问的引述一致数是**机械字符串检查**，不应宣传成“零幻觉”。

## 代表性错误

| 案例 | 预设 → 实际 | 原因与后续方向 |
| --- | --- | --- |
| `R05` | 结果 → 证据 | “交付时间”被当作已有结果，导致过早询问验证方式；需区分计划与实际交付。 |
| `R07` | 结果 → 个人行动 | “我分析了”未被当前行动词表识别；可在独立开发样本上扩充表达方式。 |
| `R08` | 结果 → 个人行动 | 英文行动描述未被中文规则识别；需明确多语言支持范围。 |
| `E06` | 证据 → 不追问 | 年份 `2025` 被当作量化证据；数字出现不等于结果得到验证。 |
| `E08` | 证据 → 不追问 | 回答出现 `30%`，同时明确说“没有做前后对比”；当前规则不理解否定。 |

报告重点也漏掉 `R06`、`R08`、`E05`、`E06`、`E08`、`T08`。例如 `T08` 已说明技术结果，报告却要求补充协作过程。这说明追问规则与报告规则需要分别评估，不能只用一个总体分数概括。

## 如何解释结果

这些数字只衡量作者编写的 40 条文本与作者预设标签的一致性。样本量小，语句形式有限，标签未经过盲审或多评审者一致性检验；不能外推到真实求职者、岗位、语言或真实模型路径。未来若获得授权数据，应增加多评审者标注、分场景误差分析、真实用户反馈和受控的模型对比，并保留 `ai` / `fallback` 来源标记。
