# EchoHire × ResumePilot：作品集说明与评测

## 问题与方案

学生写简历、准备面试和复盘时，常把三个步骤放在不同工具里，反馈很难变成下一次行动。这个双站点作品将“整理经历 → 根据岗位练习 → 检查证据 → 回写简历”连成可操作的闭环。

ResumePilot 提供结构化编辑、头像、实时预览、PDF 导出和简历优化建议；EchoHire 提供岗位面试、逐题追问、报告和职业路线。EchoHire 访客无需 ChatGPT 登录，记录只保存在当前浏览器；已登录用户的面试记录可保存在 D1。两个站点通过用户主动触发的 URL 片段交接数据，没有共享账户或后台数据库。

## 技术决策

| 决策 | 目的与边界 |
| --- | --- |
| Next.js / React / TypeScript | 两个站点独立开发与部署，界面和 API 路由在同一代码库。 |
| OpenAI Responses API | 当前 EchoHire 默认关闭付费调用，访客始终使用离线规则；未来仅在所有者显式开启并且用户已登录时才会尝试调用。 |
| D1（EchoHire） | 保存登录用户的答题进度、报告和能力画像；上传 PDF 不做长期存储。托管配置虽有 R2 绑定，当前代码未使用。 |
| localStorage（EchoHire） | 访客可免登录练习并在同一浏览器刷新恢复；清除网站数据或换设备后无法恢复。 |
| localStorage（ResumePilot） | 免注册编辑，刷新后在同一浏览器恢复；跨设备不同步。 |
| URL 片段交接 | 用户点击后跨站导入简历文本或反馈；不表示两个站点有统一身份。含私人内容的片段可能留在浏览器历史等本地环境中，不应当作安全的服务间通道。 |

## 可重复的验证

自动测试：在 EchoHire 仓库运行 `pnpm test`，检查空答案、个人贡献/结果证据追问、完整回答不重复追问、报告来源与逐题反馈、身份头校验、D1 记录映射和按用户隔离的更新条件。测试使用本地规则与 D1 mock，不需要 API Key。

另有[40 条独立虚构案例的离线评测](OFFLINE_EVAL.md)，通过 `pnpm eval:offline` 重放备用追问与备用报告。默认规则追问类型一致 35/40，追问决策一致 38/40；该结果只适用于作者编写的挑战集，不能当作在线模型或真实面试效果。

浏览器回归：`pnpm test:e2e` 使用 Playwright 和虚构数据，覆盖 mock 流程及无需登录的真实本地 API 流程，跑通创建面试、提交第一题、刷新恢复、完成四题及查看报告。测试关闭付费 API，不消耗 OpenAI 额度；它不证明真实 D1 或模型路径可用。

人工验收清单（公开访客与登录用户各可执行相应步骤）：

1. ResumePilot 输入自己的数据、上传头像、保存草稿、刷新、导出 PDF 并检查分页/中文显示。
2. 从 ResumePilot 点击“前往 EchoHire 练习”，确认岗位和简历文字导入 EchoHire，并核对页面说明：当前免费题目只使用岗位和 JD；不要把示例简历当作真实个人信息。
3. EchoHire 创建面试并提交至少一道回答，刷新后确认题目、已答内容和进度仍在；再用同一账户换设备检查云端记录。
4. 故意提交有具体行动但缺结果证据的回答，确认追问聚焦缺失信息，而不是统一提示“回答过短”。
5. 完成面试，在报告中核对 `ai`/`fallback` 状态，打开职业路线，并把反馈送回 ResumePilot。
6. 在未登录浏览器打开 EchoHire，确认可免简历完成离线面试，同一浏览器刷新可恢复，而另一浏览器看不到该访客记录。

## 尚未解决

- 在线 OpenAI 请求曾返回 `billing_not_active`；当前 EchoHire 默认关闭付费调用，未来如需启用仍需重新验证真实模型路径。
- 尚无两个站点的统一身份、云端简历草稿、可信的服务间数据同步。
- 已有一条 mock 浏览器主流程；PDF 视觉、双站点跳转、跨设备与真实 API 仍需端到端回归。
- 还没有可证明训练效果的真实用户样本，因此不应宣称提升面试成功率。

> **EchoHire × ResumePilot｜AI 求职训练工具链** — 使用 Next.js、React、TypeScript 搭建简历编辑与模拟面试双站点；实现 PDF 导出、跨站简历/反馈交接、D1 面试进度与能力画像持久化，并为追问和报告设计可识别的规则降级及离线自动化测试。

面试中可进一步解释：为什么 ResumePilot 采用本地草稿、EchoHire 采用 D1；OpenAI 不可用时如何保证任务不中断；哪些能力尚未形成真正的跨产品 Agent。不要把示例数据、测试数量或未经验证的业务提升包装成真实成果。
